# 0010. Per-route static HTML for link previews

Status: accepted
Date: 2026-09-22
Provenance: autonomous

## Context

Link-preview scrapers (Slack, LinkedIn, WhatsApp, iMessage, X) fetch raw HTML
and do not run JavaScript. Every route shipped the same `index.html`, titled
`tsznokwong.github.io`, with no Open Graph tags. `/journey` and `/travel` only
rendered through the `404.html` SPA fallback, so GitHub Pages answered them
with HTTP 404, which scrapers and search engines treat as a missing page.

## Decision

Emit an `index.html` per route at build time, each with its own `<title>`,
description, Open Graph, Twitter card and canonical tags, over relying on the
`404.html` fallback alone, because the fallback returns 404 and cannot vary
tags per route.

Do it with a Vite plugin (`scripts/route-html-plugin.ts`) over a post-build
Node script, because Vite already loads the TypeScript route list and JSON
data, and `vite preview` then serves exactly what deploys.

Tag only the static page shell over full prerendering of page content,
because scrapers need only the tags and prerendering adds a headless render
step to every build.

Route metadata lives in `src/types/page-type/routes.ts`, free of React
imports, and `PageType` extends it with page components.

## Consequences

- `/journey` and `/travel` return 200; GitHub Pages redirects them to their
  trailing-slash form, which the router and `PageType.fromPath` accept.
- A new page must be added to `routes.ts` to get its own preview; a unit test
  fails if `PageType.AllValues` and `Routes` drift.
- `404.html` stays a copy of the Home HTML for unknown paths.
- The preview image `public/og-image.png` is a committed static file; it is
  regenerated by hand when the branding changes.
